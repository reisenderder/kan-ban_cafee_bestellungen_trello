# 🛡️ ЖЕЛЕЗНЫЕ ПРАВИЛА И АЛГОРИТМЫ ПРОЕКТА DAYMOHKCOFEE

> **ВАЖНОЕ СИСТЕМНОЕ ПРАВИЛО**: Данный файл авто-загружается в начало каждой новой сессии. Все указанные ниже правила обязательны к строгому исполнению по умолчанию БЕЗ НАПОМИНАНИЙ со стороны пользователя.

---

## 📌 1. Главный Закон Разработки: `Spec -> Plan -> Code`

1. **ЗАПРЕЩЕНО** писать код или редактировать файлы реализации без предварительной проверки спецификаций в папке `specs/`.
2. Если пользователь просит добавить новое поведение или изменить функцию:
   - **Шаг 1 (SPEC GATE)**: Проверить и актуализировать соответствующую спецификацию в `specs/03_feature_specs/` или `specs/04_technical_specs/`.
   - **Шаг 2 (PLAN GATE)**: Проверить и записать задачу в активный план в `work_plans/active/`.
   - **Шаг 3 (CODE GATE)**: Только после этого выполнять изменения в коде.

---

## 📌 2. Фиксация История Изменений в `docs/CHANGELOG.md`

Каждая правка, доработка или реакция на замечание пользователя/клиента **ОБЯЗАТЕЛЬНО** записывается в файл [`docs/CHANGELOG.md`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/docs/CHANGELOG.md) с одной из 5 категорий:
* 🎨 `[DESIGN]` — Верстка, стили, карточки, шрифты, отступы.
* ⚙️ `[FEATURE]` — Бизнес-логика, кнопки, поведение форм и заказа.
* 🍳 `[KITCHEN/CRM]` — Экран повара KDS, CRM менеджера, чеки, курьеры.
* 🛡️ `[SECURITY]` — Авторизация, логины, роли, сессии.
* 🗄️ `[DATABASE]` — Таблицы Supabase, API, типы данных.

---

## 📌 3. Изоляция изменений в Git (Ветки)

1. Новые доработки и исправления делаются в изолированных ветках Git (`feat/...` или `fix/...`).
2. **ЗАПРЕЩЕНО** выполнять `git merge` самостоятельно. Слияние веток и создание Pull Request выполняет пользователь.

---

## 📌 4. Обязательная Автоматическая Проверка Сборки

Ни одна задача не считается завершенной, пока не выполнены проверки:
1. `npm run typecheck` — проверка компиляции типов TypeScript (должна вернуть `exit code 0`).
2. `npm run build` — проверка сборки страниц Next.js (должна вернуть `exit code 0`).

---

## 📌 5. Обязательный Итоговый Отчет (`project-docs-governor`)

В конце каждого ответа предоставлять краткий, структурированный отчёт:
* Что проверено и сделано.
* Какие файлы изменены.
* Результат проверки `npm run typecheck` и `npm run build`.
* Текущая ветка Git.
