## 1. Назначение плана

Настоящий план описывает пошаговую подготовку, связывание компонентов и проверку первого операционного контура проекта **DAYMOHKCOFEE в Каире** — **БЛОК 1 (Минимальный боевой запуск с Электронной Кухней)**.

Цель Блока 1 — дать кафе возможность выставить актуальные блюда на витрину, безопасно принимать заказы клиентов, общаться с ними в чате в реальном времени, вещать заказы на экран повара с контролем времени приготовления, вести операционную работу через CRM менеджера, управлять стоп-листом через панель Админа и передавать адреса курьерам через WhatsApp.

---

## 2. Состав Блока 1

В Блок 1 входят следующие ключевые узлы системы:

1. **Публичная витрина и корзина (`/`)**: 
   * Подтягивание списка блюд из таблицы `Dishes` / `MenuSlots` базы данных Supabase.
   * Динамический фильтр по категориям и боковая выдвижная корзина (`CartDrawer.tsx`).
   * Мгновенный учёт доступности блюд (`is_available = false` скрывает/запрещает заказ).

2. **Верификация клиента и Оформление (`OtpVerificationModal.tsx`)**:
   * Ввод имени, телефона в Каире, адреса доставки и ориентира.
   * 6-значный OTP-код верификации (SHA-256 хэширование).

3. **Страница заказа и Живой Чат (`ChatMessage` + Supabase Realtime)**:
   * Создание заказа `Order` и выдача клиенту токена доступа `ClientOrderAccess`.
   * Двусторонний чат клиента с менеджером в реальном времени без перезагрузки страницы.

4. **Электронный экран Кухни (`/kitchen/dashboard`) & Таймер готовки**:
   * Экран повара (для планшета/ТВ) с автоматическим обзором заказов в статусе `COOKING`.
   * **Фиксация и анализ времени готовки**:
     * Нормативное время приготовления заказа (`target_cooking_time_minutes`).
     * Автоматическое засекание `cooking_started_at` при отправке на кухню.
     * Таймер обратного отсчета (зеленый -> желтый -> красный при превышении нормативного времени).
     * Фиксация `cooking_completed_at` при нажатии поваром кнопки **«ГОТОВО»**.
     * Поле фиксации причины задержки (`delay_reason`), если кухня не уложилась в норму (для аналитики менеджера/владельца).

5. **CRM-Канбан Менеджера (`/manager/crm`)**:
   * Логин менеджера через Supabase Auth (`email` + `password`).
   * Операционный канбан в стиле Sunsama: перетаскивание/перевод статусов заказа (`NEW` -> `COOKING` -> `DELIVERING` -> `CLOSED`).
   * Кнопка **«Скопировать для WhatsApp»** для мгновенной отправки состава и адреса заказа курьеру.
   * Восстановление печати бумажного чека (`KitchenTicketPrint.tsx`) при необходимости.

6. **Панель Администратора (`/admin/dashboard`)**:
   * Вход владельца/администратора по логину через Supabase Auth.
   * **Управление Меню**: включение/выключение блюд в стоп-лист, редактирование цен и установка стандартного времени приготовления блюд.
   * **Управление Сотрудниками**: контроль жизненного цикла учетных записей (`ACTIVE` / `DISABLED` / `ARCHIVED`).
   * **Просмотр жалоб**: вкладка для фиксации обращений.

7. **Курьерский фоллбэк через WhatsApp**:
   * Ручное взаимодействие менеджера с курьерами без обязательного использования курьерского приложения на первом этапе.
   * WhatsApp используется только как временный канал передачи и координации. Он не реализует целевые ограничения доступа курьера, статусы доставки, QR-подтверждение и журнал действий из `Feature_Courier_Delivery.md`.

## 3. Временные исключения из Блока 1

Для максимального ускорения первого запуска в Блок 1 НЕ входят:
* ❌ Рабочий кабинет курьера (`/courier/dashboard`) и QR-сканирование токенов доставки. На этом этапе они **временно отложены**, а не заменены на уровне целевого продукта; для операционной передачи используется WhatsApp.
* ❌ Рабочий кабинет Урегулирования (`/resolution/cases`). Менеджер обрабатывает обычные операционные отклонения, фиксирует и вручную передает сложные случаи, но не получает полномочия роли `RESOLUTION_OFFICER`: не снимает желтый/красный риск и не принимает от имени отдела финальное решение о возврате.

Эти исключения являются границами этапа Block 1. Целевые курьерские и resolution-сценарии остаются определены в Feature Specs и должны реализовываться отдельными последующими блоками.
