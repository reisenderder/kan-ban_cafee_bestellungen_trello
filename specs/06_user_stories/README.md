# User Stories

## Назначение раздела

Этот раздел хранит пользовательские истории, сценарии и критерии приемки после Global Spec, Functional Map, Feature Specs и Technical Specs.

User Stories отвечают на вопрос: как конкретный участник системы проходит путь, какой результат он должен получить и какие отклонения система обязана обработать.

## Правила раздела

1. Каждая история должна ссылаться на утвержденные или текущие спецификации верхнего уровня.
2. User Stories не выбирают фреймворк, базу данных, API или инфраструктуру.
3. User Stories должны проверять happy path, отклонения, роли, видимость данных и критерии приемки.
4. Если открытый вопрос можно закрыть без противоречия верхним документам, решение фиксируется в разделе `Закрытые решения`.
5. Если вопрос нельзя закрыть без изменения Global Spec или Functional Map, он остается в разделе `Открытые вопросы`.

## Текущие документы

На 2026-09-01 — **72 пользовательские истории в 8 рабочих документах**, матрица трассировки и два check report.

### Рабочие документы User Stories

1. `User_Stories_MVP_Order_Flow.md` — 13 сквозных историй потока заказа от витрины до доставки, возврата, скидочной продажи, жалобы и урегулирования (`US-01…US-13`). `US-02`, `US-12`, `US-13` — краткие сквозные истории со ссылками на детальные документы.
2. `User_Stories_Order_And_Client_Access.md` — оформление заказа (`US-ORDER-01…03`, `US-VERIFY-01…02`) и жизненный цикл доступа клиента после создания заказа (`US-ACCESS-01…04`); сюда вынесены пошаговые сценарии перегруженной `US-02`.
3. `User_Stories_Kitchen_KDS.md` — электронная кухня (`US-KDS-01…06`): очередь, ограниченный состав данных, таймер, идемпотентная готовность, обновление CRM и бумажный fallback.
4. `User_Stories_Admin_Access_Menu.md` — администрирование, сотрудники, роли, вход и сессии, жалобы, журналы (`US-ADM-01…10`).
5. `User_Stories_Menu_Availability.md` — управление меню, ценами, доступностью блюд и влиянием на корзину (`US-MENU-01…10`).
6. `User_Stories_Discount_Admin.md` — скидочные товары, административные права, покупка, конкурентная продажа, списание, журналы (`US-DISC-01…08`).
7. `User_Stories_Resolution_And_Risk.md` — операционный жизненный цикл кейса урегулирования (`US-RES-01…05`) и самостоятельный жизненный цикл жёлтой и красной записи риска (`US-RISK-01…05`); сюда вынесены пошаговые сценарии перегруженной `US-13` и правила риска из `US-10`.
8. `User_Stories_Complaints.md` — полный путь жалобы клиента (`US-COMP-01…04`): подача с номером заказа или без, автоматическое подтверждение, обработка администратором, закрытие и soft delete; сюда вынесены пошаговые сценарии `US-12`. Вложения к жалобе — post-MVP.

### Трассировка и отчёты проверки

* `User_Stories_Traceability_Matrix.md` — матрица `Global принцип → функциональная зона → Feature Spec → Technical Spec → User Story`; обратная проверка источника каждой истории; статус разделов «User Stories должны проверить».
* `User_Stories_All_Check_Report.md` — отчёт проверки всего слоя (структура, покрытие Feature/Technical Specs, противоречия, post-MVP границы).
* `User_Stories_MVP_Order_Flow_Check_Report.md` — отчёт проверки сквозного документа потока заказа.
