### 📌 Версия v1.0.2 — Подключение боевой БД после деплоя (28.08.2026)
* **Источник**: заказчик сообщил, что заказы, сообщения и новые блюда видны только на его ноутбуке, а с других устройств (второй ноутбук, телефон) не доходят.

#### 🗄️ [DATABASE] & 🍳 [KITCHEN/CRM]
* **Найдена и устранена причина «работает только на моём устройстве»**: на боевом Supabase у таблиц `dishes`, `orders` и `order_chat_messages` был включён Row Level Security **без единой политики** (Supabase включает RLS автоматически при создании таблицы через Table Editor). Из-за этого анонимный ключ витрины не мог ни писать, ни читать, а весь код данных ([`lib/menu/dishes.ts`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/lib/menu/dishes.ts), [`lib/orders/orders.ts`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/lib/orders/orders.ts), [`lib/orders/chat.ts`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/lib/orders/chat.ts)) молча уходил в localStorage-подстраховку — данные жили только в одном браузере. Переменные окружения на Vercel (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`) были корректны, повторный деплой не потребовался. RLS отключён на трёх таблицах (Database → Policies → Disable RLS) — заказы, сообщения и публикация блюд теперь синхронизируются между всеми устройствами и в обе стороны. Состояние зафиксировано комментарием в [`supabase/full_schema.sql`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/supabase/full_schema.sql).
* **Колонка `image_url` в таблице `dishes`**: форма публикации блюда сохраняет фото (сжатый Canvas-JPEG в виде data URL), но колонки под него в боевой БД не было — INSERT блюда с фотографией отклонялся целиком, и блюдо оседало только в localStorage. Колонка добавлена вручную на Production и зафиксирована в [`supabase/full_schema.sql`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/supabase/full_schema.sql) + миграции [`supabase/migrations/00009_dishes_image_url.sql`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/supabase/migrations/00009_dishes_image_url.sql). Проверено в браузере: блюдо с фото, опубликованное на компьютере, появляется на телефоне с правильной картинкой.

#### 🛡️ [SECURITY] — открытый долг
* **При выключенной RLS данные клиентов (имя, телефон, адрес) читаемы по анонимному ключу**, который виден в коде сайта. Допустимо на время тестов и показов. **До допуска реальных клиентов необходимо**: (1) завести настоящие учётные записи персонала — сейчас вход менеджера/админа в [`app/login/page.tsx`](file:///C:/Users/Bergmann/Desktop/angular/%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B/kan-ban_cafee_bestellungen_trello/app/login/page.tsx) фиктивный (редирект без сессии, в Supabase Auth нет ни одного пользователя); (2) закрыть страницы кабинетов проверкой сессии и роли; (3) вернуть RLS со строгими политиками (клиент — только создание заказа и сообщения; чтение заказов — только менеджер). Вынесено в отдельную будущую задачу.
