## 1. Назначение раздела

Здесь хранятся результаты сплошной ревизии проекта по двадцати двум зонам аудита.

Раздел содержит **наблюдения, а не требования**. Записанное здесь не является утверждённым поведением системы и не изменяет `../../specs/`. Находка становится работой только после того, как войдёт в отдельный план исправлений.

Требования живут в `../../specs/`, планы работ — в `../../work_plans/`, история изменений — в `../CHANGELOG.md`.

---

## 2. Как читать отчёты

1. **Сводка** — `Audit_Summary.md`. Начинать отсюда: итоги, метрики, приоритизация.
2. **Реестр находок** — `Findings_Register.md`. Единая таблица всех находок с сортировкой по критичности.
3. **Отчёт по зоне** — файлы `00`–`25`. Полная карточка каждой находки и доказательства.

Каждая находка имеет идентификатор вида `AUD-<эпик>-<NNN>`, критичность `S0`–`S4`, статус и тип. Расшифровка — в разделе 4 плана.

Все ссылки вида `файл:строки` относятся к базовому коммиту аудита, зафиксированному в `00_Baseline_And_Inventory.md`.

## 4. Правила раздела

1. Отчёты создаются только в рамках плана `../../work_plans/active/Work_Plan_Project_Audit.md`.
2. Каждое утверждение в отчёте сопровождается доказательством: ссылкой на строки кода, дословной цитатой из документа или фактическим выводом команды.
3. Оценочные формулировки без доказательства не допускаются. Непроверенное утверждение получает статус `NOT-VERIFIED` с указанием причины.
4. Отчёты не изменяют `../../specs/` и не создают требований.
5. Отчёты не удаляются и не переписываются последующими аудитами: повторная ревизия оформляется отдельным планом и отдельным набором артефактов.
6. Статус в таблице раздела 3 обновляется по мере создания каждого файла.
